# SP · SAS Field Notes

## 两层架构（V0.3.0 起）

- **速查**：`public/sas-notes/index.html`，统一编号 01、02……；正文只放问题、结论、短代码、必要边界；原生折叠目录、首页置顶规则持续有效。
- **系统专题**：`public/sas-learning/index.html` 及 `public/sas-learning/{sql,freq,statistics,power,graphics}/index.html`；用于用户要求“基础到进阶”或教程级理解的内容，以真实疑问推动叙述（观察现象 → 思考原因 → 最后解决和验证），不强制采用基础/实战/进阶三个级别；需要多少段由问题决定。
- **回顾进度**：`docs/sas-learning-roadmap.md` 记录真实历史讨论、证据边界、后续积累的主题。历史聊天回顾不等于代码已验证。
- **新增专题**：更新对应 HTML、`public/knowledge-index.json`、`public/sitemap.xml`，必要时增加首页入口；避免无效功能。
- **示例标识**：只用匿名或公开的 `sashelp.*` 示例；未经用户实际运行验证的示例，应明确标为官方语法教学代码。不能因为出现在网页就宣称已经在 SAS 运行。
- **保留原始问题**：涉及 `PROC REPORT` ODS RTF、Raw RTF `~R'...'` 时，必须区分 SAS 通用语法与目的地特定排版代码；记录实际版本差异。

## 深度原则（V0.3.1 起）

- **简洁不是删掉理解所需的信息。** 速查页优先快速定位，但当概念、计算公式、原因与 QC 解释属于同一个问题时，应直接讲清楚（如 PROC REPORT 组标题与 RTF 控制），不能只给函数名和结论。
- **PK 浓度 Table 必需统计量**：N、n、n of BLQ、Mean、SD、CV%、Median、Min、Max、GeoMean、GeoSD、GeoCV%（历史 Shell 可能命名 Geostd/CVB%，须以 Shell/Spec 为准）。解释统计含义、原尺度/对数尺度、零与 BLQ、计算条件、n 与 N 的不同。**GeoCV% ≠ SD/GeoMean**，而是 `100*sqrt(exp(sd(log(x))**2)-1)`。
- **PK 参数的特殊情况**：如 Tmax 仅显示 n/Median/Min/Max，特殊的 NC/NA、BLQ 阈值、分析标志与 PPCAT/PPTPTREF 的选择皆为项目规则，严禁普适化。
- **PROC REPORT**：跨列标题和 RTF 排版统一归于速查笔记 06；内部清楚区分 COLUMN 结构、STYLE、CELLWIDTH、原生 RTF 控制字与版面 QC，不再单设系统专题。
- **案例+推理**：公式解释要附至少一个最小数值算例或可运行结构示例；凡 SAS/Word 环境未实际执行，只能标记“教学/待运行验证”。
- PK 浓度专题保留 `/sas-learning/pk-concentration/`；REPORT/RTF 统一维护在 `/sas-notes/#note-06`；速查笔记编号连续 01–09，旧 #note-10 指向合并后的 06。

## 站点视觉与代码交互（V0.3.2）

- 新增/维护静态 HTML 页必须引入 `/assets/style.css` 与 `/assets/code-copy.js`（带最新版本查询参数）。不要为每页另写一套复制脚本。
- 教学代码应采用 `<pre><code>...HTML 转义后的源代码...</code></pre>`，共享脚本自动生成复制按钮。不要把按钮文字混入代码内容。
- 保持 PC 文字可读性与手机端的平衡：PC 端在全局 CSS 中集中维护对比度；不要在个别页面用更浅的行内颜色覆盖。
- 复用的组件应优先集中到 `public/assets/`，保证后续新增 SAS 代码页自动获得按钮。

- 代码按钮文字使用英文 `Copy` / `Copied` / `Failed`。可悬停设备默认隐藏，hover 或键盘聚焦时显示；触屏常显确保可触达。全站共用 `/assets/code-copy.js` 和 `/assets/style.css`，不可在各页重复创建。

## 问题驱动的叙述原则（V0.3.4）

- **先有现象，再有语法**：从实际问题或异常开篇，让读者知道为什么要读下去。
- **推理自然展开**：现象、困惑、原因、代码、结论与 QC 视内容自然交织；这不是五个固定栏目。
- **不套课堂级别**：禁止机械使用“基础/实战/进阶”或“Level 1/2/3”，不为凑数量补废话。
- **长短依内容决定**：CATX 快速对照短；CV/GeoCV、BLQ、跨列标题与原始 RTF 要说明机制、算例和边界。
- **同一问题尽量放一起**：PROC REPORT COLUMN 分组与 RTF 控制合并在笔记 06，另设专题的旧 URL 只负责跳转。
- **代码 Copy 不占空间**：代码框默认正常高度，右上角悬浮 Copy；PC hover/focus 出现，触屏保持可点，不再预留 41px 空白。
- **保持可检索**：目录折叠、连续编号、锚点稳定；系统专题用真实疑问作为标题。

## 宗旨

**人狠话不多。只保留未来能帮自己解决问题的内容。**
内容以实际工作中遇到的疑难点为准，不追求教材式全面解释、不重复用户已懂的背景。

## 触发条件

- 用户要求把某次 SAS、SDTM、ADaM、TFL、QC 问题加入 `sp.769967.xyz` 笔记。
- 用户要求新增、改写、精简 `public/sas-notes/index.html`。
- 用户希望沉淀工作中反复遇到的统计编程问题。

## 写作硬规则

1. **连续编号**：按 `01`、`02`、`03`……排列。标题与目录编号必须一致；既有编号保持稳定，不随分类调整。
2. **一条只讲一个问题**：同一问题的现象、根因、处理方法放在同一条；若是可独立检索的概念（如 `PUT / INPUT`），才独立成条。
3. **可变的最小结构**：
   - **标题**：`NN + 技术关键词 / 问题`；能靠标题搜索找到。
   - **结论/根因**：根据情境先提出问题或记录现象，再解释原因与解决方案；简单的问题一句话即可。
   - **关键代码**：尽量 3–12 行、直接复制可用；无必要时不写测试工程。
   - **边界**：只有确实会导致错误或误用时才补 1 句。
4. **删除冗余**：不写开场寒暄、反复总结、无关背景、长示例、重复表格、伪需求组件、额外教程。压缩重复，不按字数硬截；概念与原理需要讲到读者真正理解。
5. **正确性优先**：区分用户已经实测的修复与推断；无法运行 SAS 就不要宣称“已在 SAS 验证”。有边界（例如 `99.95-high = '(100)'` 会吞掉超过 100 的值）必须点明。
6. **易检索**：标题里保留原始函数名、变量名或报错关键词，比如 `CAT/CATS/CATX`、`PROC FORMAT`、`INPUT`、`PUT`、`PICTURE`。
7. **保护数据**：只能使用虚构/脱敏示例；不要把受试者、申办方、项目源数据、私人信息或内部文件放到公开网站。
8. **保持原站风格**：延续极简白底、轻量表格、低干扰配色，不添加复杂组件、无关动画或后台服务。
9. **函数速查的特例**：用户明确要求汇总一组相关的 SAS 函数时，可在单条笔记中按用途分组为紧凑表格，列出“函数｜最短示例｜一句话说明”，不受普通条目 120–180 字建议限制；仍不添加教学长文。高频函数用 `<strong><code>函数名</code></strong>` 加粗，低频不加粗。必须覆盖用户列举的函数与对应函数（如 `UPCASE/LOWCASE`、`NMISS/CMISS`），必要时用一句话提示类型或边界。
10. **优先维护已有索引**：例如“拼接那一块”优先扩写 `04`，不要把同一主题拆成多条重复笔记。

## 维护流程

1. 读取 GitHub 仓库 `dengweizhang/sp` 当前的 `public/sas-notes/index.html`，**不要凭对话记忆覆盖站点最新内容**。
2. 确认问题是新条目还是既有条目的修订。修订原条目不重复编号；新增条目使用下一个编号。
3. 更新可折叠目录 `details.sas-toc > nav` 中的 `href="#note-NN"` 与正文 `section#note-NN`，一一对应。使用原生 `<details>`/`<summary>`，默认收起，无需 JavaScript。
4. 新增条目放入 `SP_NOTES_START` 与 `SP_NOTES_END` 注释之间；不破坏其他笔记。
5. **首页置顶约定**：`public/index.html` 中 `/sas-notes/` 始终是文章目录第一条；其他文章依次排列。首页文章序号与本页独立笔记编号是两套序列，不要混用。
6. 仅在必要时更新 `public/knowledge-index.json` 中 SAS 笔记条目的关键词；新增/修改站点版本号时保持首页、正文页、README 中一致。
7. 校验：编号连续且无重复、锚点有效、HTML 合法、代码已做静态检查、敏感内容为零、没有过长文本。
8. 提交 GitHub，并向用户给出笔记链接与具体变更。**GitHub 提交不等于 Cloudflare 已上线**；除非真实打开生产页面验证，否则不要声称已部署完成。

## 最小内容模板

```html
<section class="sas-note" id="note-NN" aria-labelledby="title-NN">
  <h2 id="title-NN"><span class="sas-no">NN</span>技术关键词：具体问题</h2>
  <p><strong>根因/结论：</strong>一句话解释。</p>
  <pre class="sas-code"><code>关键 SAS 代码（HTML 特殊字符须转义）</code></pre>
  <p class="sas-boundary"><strong>注意：</strong>仅在必要时保留边界条件。</p>
</section>
```

目录新增对应项（插入现有可折叠 `<details class="sas-toc"><summary>目录 · NN 条笔记</summary><nav>…</nav></details>` 的 `nav` 内）：

```html
<a href="#note-NN"><span class="sas-no">NN</span>技术关键词：具体问题</a>
```

目录显示数量与真实条目数同步更新。

## 整理步骤（内容层）

- 附必要边界，保持可以由后来者独立理解
