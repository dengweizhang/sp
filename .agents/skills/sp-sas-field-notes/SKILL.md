# SP · SAS Field Notes

## 宗旨

**人狠话不多。只保留未来能帮自己解决问题的内容。**
内容以实际工作中遇到的疑难点为准，不追求教材式全面解释、不重复用户已懂的背景。

## 触发条件

- 用户要求把某次 SAS、SDTM、ADaM、TFL、QC 问题加入 `sp.769967.xyz` 笔记。
- 用户要求新增、改写、精简 `public/sas-notes/index.html`。
- 用户希望沉淀工作中反复遇到的统计编程问题。

## 写作硬规则

1. **连续编号**：按 `01`、`02`、`03`……排列。标题与目录编号必须一致；既有编号保持稳定，不随分类调整。
2. **一条只讲一个问题**：同一问题的现象、根因、处理方法放在同一条；若是可独立检索的概念（如 `PUT / INPUT`），才独立成条。
3. **固定最小结构**：
   - **标题**：`NN + 技术关键词 / 问题`；能靠标题搜索找到。
   - **结论/根因**：通常 1–2 句，直接回答“为什么 / 怎么办”。
   - **关键代码**：尽量 3–12 行、直接复制可用；无必要时不写测试工程。
   - **边界**：只有确实会导致错误或误用时才补 1 句。
4. **删除冗余**：不写开场寒暄、反复总结、无关背景、长示例、重复表格、伪需求组件、额外教程。每条重点文字尽量不超过 120–180 个汉字（代码除外）。
5. **正确性优先**：区分用户已经实测的修复与推断；无法运行 SAS 就不要宣称“已在 SAS 验证”。有边界（例如 `99.95-high = '(100)'` 会吞掉超过 100 的值）必须点明。
6. **易检索**：标题里保留原始函数名、变量名或报错关键词，比如 `CAT/CATS/CATX`、`PROC FORMAT`、`INPUT`、`PUT`、`PICTURE`。
7. **保护数据**：只能使用虚构/脱敏示例；不要把受试者、申办方、项目源数据、私人信息或内部文件放到公开网站。
8. **保持原站风格**：延续极简白底、轻量表格、低干扰配色，不添加复杂组件、无关动画或后台服务。
9. **函数速查的特例**：用户明确要求汇总一组相关的 SAS 函数时，可在单条笔记中按用途分组为紧凑表格，列出“函数｜最短示例｜一句话说明”，不受普通条目 120–180 字建议限制；仍不添加教学长文。高频函数用 `<strong><code>函数名</code></strong>` 加粗，低频不加粗。必须覆盖用户列举的函数与对应函数（如 `UPCASE/LOWCASE`、`NMISS/CMISS`），必要时用一句话提示类型或边界。
10. **优先维护已有索引**：例如“拼接那一块”优先扩写 `04`，不要把同一主题拆成多条重复笔记。

## 维护流程

1. 读取 GitHub 仓库 `dengweizhang/sp` 当前的 `public/sas-notes/index.html`，**不要凭对话记忆覆盖站点最新内容**。
2. 确认问题是新条目还是既有条目的修订。修订原条目不重复编号；新增条目使用下一个编号。
3. 更新可折叠目录 `details.sas-toc > nav` 中的 `href="#note-NN"` 与正文 `section#note-NN`，一一对应。使用原生 `<details>`/`<summary>`，默认收起，无需 JavaScript。
4. 新增条目放入 `SP_NOTES_START` 与 `SP_NOTES_END` 注释之间；不破坏其他笔记。
5. **首页置顶约定**：`public/index.html` 中 `/sas-notes/` 始终是文章目录第一条；其他文章依次排列。首页文章序号与本页独立笔记编号是两套序列，不要混用。
6. 仅在必要时更新 `public/knowledge-index.json` 中 SAS 笔记条目的关键词；新增/修改站点版本号时保持首页、正文页、README 中一致。
7. 校验：编号连续且无重复、锚点有效、HTML 合法、代码已做静态检查、敏感内容为零、没有过长文本。
8. 提交 GitHub，并向用户给出笔记链接与具体变更。**GitHub 提交不等于 Cloudflare 已上线**；除非真实打开生产页面验证，否则不要声称已部署完成。

## 最小内容模板

```html
<section class="sas-note" id="note-NN" aria-labelledby="title-NN">
  <h2 id="title-NN"><span class="sas-no">NN</span>技术关键词：具体问题</h2>
  <p><strong>根因/结论：</strong>一句话解释。</p>
  <pre class="sas-code"><code>关键 SAS 代码（HTML 特殊字符须转义）</code></pre>
  <p class="sas-boundary"><strong>注意：</strong>仅在必要时保留边界条件。</p>
</section>
```

目录新增对应项（插入现有可折叠 `<details class="sas-toc"><summary>目录 · NN 条笔记</summary><nav>…</nav></details>` 的 `nav` 内）：

```html
<a href="#note-NN"><span class="sas-no">NN</span>技术关键词：具体问题</a>
```

目录显示数量与真实条目数同步更新。

## 整理步骤（内容层）

- 用户原问题 → 提取独立可复用的知识点（尽量 1 个，不合并不相关内容）
- 去除讨论过程中的失败尝试、重复纠正、长背景（**必要的反例和风险除外**）
- 用最短代码承载最后有效的解决方案
- 附必要边界，保持可以由后来者独立理解
- 核实与现有条目是否重复，重复则更新原条目
