C-QTc：从 ADEG + ADPC 到浓度–效应分析

从实际疑问开始

常规 ADEG 能回答“给药后 QTcF 变了吗、多少人超过阈值”；C-QTc 则试图回答“血药浓度越高，QTcF 是否系统性延长，以及在临床相关暴露下可能延长多少”。它是分析模块，不是一个新的 SDTM Domain；可以复用 ADEG，但还需要 ADPC 及研究方案定义的配对/模型规则。

1. 它和 ADEG 常规分析有什么不同？

问题常规 ADEGC-QTc
分析对象ECG 测量和变化药物浓度与 ECG 变化的联系
横坐标访视或给药后时间也看时间，但核心模型关注浓度
常用输出描述统计、Shift、异常阈值 n(%)时间曲线、浓度–效应散点、模型预测及 90% CI
数据来源EG → ADEGEG/ADEG + PC/ADPC + ADSL 等
关键注意基线、重复测量、分析标志再加 ECG–PK 时间匹配、安慰剂校正及模型假设

你可以把 ADEG 理解为 effect 的测量基础，把 ADPC 理解为 exposure 的逐时间点浓度来源。两者一经正确匹配，就有了探索浓度–QTc 关系的基本记录。

2. 一个 Δ、两个 Δ：把 CHG 思路延长一步

ΔQTcFDelta：较基线变化值

给药后 QTcF − 基线 QTcF
相当于常见 ADEG 的 CHG。

ΔΔQTcFDouble Delta：双重差值

试验药组平均 ΔQTcF − 安慰剂组平均 ΔQTcF（同一分析时间点的简化比较）。

两个三角形不是“连续扣两次基线”。第一步消除自身基线水平差异，第二步通过同期安慰剂组的变化，帮助剥离非特异性的时间效应。ΔHR、ΔΔHR 也遵循相同逻辑。

下列全部是虚构的同时间点组均值，单位 ms。这个小计算器只展示简单差值；不代表正式 C-QTc 混合效应模型结果。

试验药 ΔQTcF+15.0 ms
安慰剂 ΔQTcF+5.0 ms
ΔΔQTcF+10.0 ms

如果没有合适的安慰剂对照，则不能照搬这个双重差值公式；必须结合研究设计与 SAP 决定如何估计或解释药物效应。即使存在安慰剂组，模型估计的安慰剂校正效应也不一定等于未调整的组均值差。

3. 已有 ADEG 和 ADPC，下一步如何接起来？

EG → ADEG同一 ECG 测量的 QT、RR、QTcF、HR、基线、CHG、ECG 实际采集时间
PC → ADPC同一分析物的浓度、单位、实际采血时间、给药相对时间、BLQ 状态
按研究规则匹配 → C-QTc 分析记录受试者 + 给药周期/队列 + 时间匹配 + 有效 ECG/PK + 分析人群 → 描述统计、绘图、建模
受试者给药后时间ADPC 浓度ADEG QTcFΔQTcF
虚构 A1 h20 ng/mL415 ms+5 ms

虚构 A4 h100 ng/mL430 ms+20 ms

示意基线为 410 ms，以上浓度、时间和结果完全虚构，未使用任何项目数据。

这里的难点不是 SQL JOIN 语法，而是 实际采血时间与 ECG 时间不完全相同。不能简单认定 ATPTN 相同就一定可以配对；允许的时间差、匹配窗口、重复 ECG 处理和缺失/BLQ 规则，都要由具体分析计划定义。

另一个高频误区：C-QTc 的 HR 应使用与 ECG 方法一致的心率测量，不能无条件把 VS 的 PULSE 替换进来；需要的是逐时间点的浓度（通常来自 ADPC），而不是只用 ADPP 的 Cmax、AUC 概括每条 ECG 观测。

4. 常见 Shell 可以分成三组

Shell 类型在回答什么SP 关注点
描述统计表HR、QTcF、ΔHR、ΔQTcF；不同组/时点的 n、Mean、SD、Median、Min/Max分析集、参数、基线、重复测量和时点
时间变化曲线均值或安慰剂校正值随给药后时间如何变化时间顺序、CI/SE/SD 定义、分组和缺失
浓度–效应图 / 模型浓度与 QTcF 变化是否相关；最高临床相关暴露下的预测效应ECG–PK 配对、协变量、重复测量相关性、模型拟合与 90% CI

注意区分：按时间点算出的原始均值之差、经过模型调整的安慰剂校正效应、浓度–效应模型预测结果，不是一个统计量。带 90% CI 的散点趋势图也不能自动替代正式模型分析。

在适用的 ICH E14/S7B 浓度–反应框架下，常见监管判断关注：最高临床相关暴露水平处，模型估计 QTc 效应的双侧 90% CI 上限是否低于 10 ms。这需要满足研究设计、数据质量、模型与覆盖暴露范围等前提，不能仅用图形斜率判定。

5. C-QTc 是否一定要新建 ADCQTC？

不一定。“C-QTc”描述分析目的，不代表 CDISC 标准要求必须有一个固定名称的 ADCQTC 数据集。若现有 ADEG 已保留足够精度、可追溯且分析就绪的信息，可在适用的数据结构中扩展；若需要合并 PK 时间匹配、分析队列或模型专用变量，也可以根据项目需要建立独立分析数据集。名称、结构和变量遵从项目 Spec 与 ADaM 原则。

建议先做数据流检查，而不是立即造新 Domain：

/* 教学伪代码：不是可直接执行的项目程序 */
ADEG: USUBJID, ECG_DATE_TIME, PARAMCD, AVAL, BASE, CHG
ADPC: USUBJID, PK_SAMPLE_TIME, ANALYTE, CONC
ADSL: USUBJID, CQT_SET_FLAG, COHORT, TRT
MATCH: subject + period + protocol-defined time window
OUT: paired concentration + ECG effect + analysis metadata

数据结构为教学示例，ECG_DATE_TIME、PK_SAMPLE_TIME、CONC、CQT_SET_FLAG 是占位逻辑名，不保证是 CDISC 标准变量名。实际字段以 ADaM Spec 为准。

6. SP 需要优先 QC 的六个问题

  1. 人群：Safety Set 与 C-QTc Set 不能默认等同；是否需要可评价的 ECG–PK 对？
  2. 参数：QTcF 的公式和 RR 单位是否一致？HR 来自 ECG 还是 VS？
  3. 基线：首次给药前最近一次，还是 time-matched baseline？是否与模型一致？
  4. 匹配：PK 与 ECG 实际时间差、跨天、跨周期、同一时点三次 ECG 如何处理？
  5. 缺失与 BLQ：浓度不可定量、缺少安慰剂时点、缺少基线时是否保留？
  6. 统计层次：个体 CHG、组均值差、模型效应和 90% CI 是否分别核对？

所有规则都应当由 Protocol / SAP / C-QTc Analysis Plan / Spec 明确，不应根据示意 Shell 推断成普适规则。

7. 下一步值得真正动手做什么？

问题 A：一名受试者有三次 ECG、一条 PK 浓度，该如何配对？

先判定 ECG 三次是独立记录还是需要按方案在时间点内取均值；再核实配对的是 ECG 实际采集时间、均值记录对应的时间，还是名义时间。不能先合并，再倒推医学规则。

问题 B：ΔΔQTcF 要不要放入每一名受试者的 ADEG？

未必。安慰剂校正通常基于组/时间点比较或统计模型，并非每名试验药受试者天然拥有一条个人 ΔΔQTcF。先弄清 Shell 展示和模型需要何种记录粒度。

问题 C：有了散点图和一条回归线，就能评价 QT 风险了吗？

不能。还需要验证浓度覆盖范围、时间效应、潜在滞后（hysteresis）、模型形式和拟合诊断，最后在预先定义的暴露水平给出带不确定性的效应估计。

推荐学习顺序：Δ/ΔΔ → 时间匹配 → C-QTc 分析数据集 → 描述性 TFL → 浓度–效应模型 → QC。本页作为后续讨论的第一版笔记。
