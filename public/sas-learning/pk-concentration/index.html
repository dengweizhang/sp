01 · 浓度 Table 的统计量清单

以我们讨论过的 PK Concentration Summary Shell 为结构参考：按分析物、给药组和采样时点分层。字段标签可能写成 BQL / BLQ、GeoMean / Geomean、GeoCV% / CVB%，以实际 SAP / Table Shell 为准。

统计量含义你应如何解释
NPK 分析集分母（受试者数）该组属于 PK 分析集的人数，通常不随采样时点变化
n实际可用于该时点统计的浓度数通常为非缺失有效分析值数；不能直接等同于 N
n of BLQ低于定量下限的观察数体现该时点低浓度数据占比与数据可解释性
Mean算术均值原尺度平均浓度，较易受很高的个体浓度影响
SD标准差原尺度离散程度，与浓度同单位
CV%算术变异系数（%）SD 相对 Mean 的大小，便于跨时间点比较相对变异
Median中位数（P50）对极端高值较不敏感的典型浓度
Min / Max最小值、最大值展示个体范围，及时发现异常单位或离群值
GeoMean几何均值基于 ln(浓度) 平均再反变换；适用于全部为正的分析数据
GeoSD几何标准差通常为 exp[SD(ln(浓度))]，是无单位的乘法型离散因子
GeoCV%几何变异系数（%）由 ln(浓度) 的方差计算，与算术 CV% 不是一回事

特别注意：历史 Shell 有 Geostd 和 CVB% 这样的列名。GeoSD 有时可能被用于指代对数尺度 SD，CVB% 也可能在某些分析中有特定含义；上表按通常的描述统计公式讲解，正式映射必须核对 Shell 脚注和 Spec。

02 · Mean、CV% 与几何统计量，区别在哪里？

算术尺度：描述实际浓度的大小及波动

Mean = Σx / n
SD = sqrt( Σ(x − Mean)² / (n − 1) )
CV% = 100 × SD / Mean

Mean 用加法计算平均值；SD 反映典型值与均值的离散程度；CV% 把 SD 转为相对百分比。例如 CV%=50%，意思是标准差约等于算术均值的一半，并非“有 50% 的受试者偏离均值”。

对数尺度：描述倍数变化与相对离散

y = ln(x)，只对正值有效
GeoMean = exp( Mean(y) )
GeoSD = exp( SD(y) )
GeoCV% = 100 × sqrt( exp( SD(y)² ) − 1 )

GeoMean 代表乘法尺度的中心，右偏数据中往往比算术 Mean 更接近主体人群的典型浓度。GeoSD 不是通常意义的“浓度单位的标准差”：例如 GeoSD=2 意味着以 GeoMean 为中心的乘法因子是 ×2 / ÷2。GeoCV% 根据对数尺度方差转换得到相对变异程度；两种 CV 在大幅偏态的数据中可能差很多。

当数据近似对数正态时，约 68% 的观察值可落在 [GeoMean/GeoSD, GeoMean×GeoSD] 附近。这是依赖分布假设的解释，不是所有样本的保证。

03 · 用三个浓度看出本质差异

示意数据：10、20、40 ng/mL，三个值围绕 20 以「×2、÷2」变化。

04 · SAS 实现：原尺度和对数尺度分开汇总

先用 PROC SUMMARY 算 Mean/SD/CV%，再对正值取 LOG() 算几何统计量，最后合并。下面可复制学习；正式代码仍需先从 ADPC 选择正确的分析标志、剂量组、分析物、参考时间与唯一记录。

/* 演示用受试者浓度值，不代表真实 PC/ADPC 数据 */
data pk_demo;
  length usubjid $8 trt $8 blqfl $1;
  input usubjid $ trt $ tpt aval1 blqfl $;
  if aval1 > 0 then ln_aval = log(aval1);
datalines;
01 A 1 10 N
02 A 1 20 N
03 A 1 40 N
01 A 2 0 Y
02 A 2 12 N
03 A 2 24 N
;
run;

/* ① 原尺度：NOBS / Mean / SD / CV / 中位数 / 极值 */
proc summary data=pk_demo nway;
  class trt tpt;
  var aval1;
  output out=arith(drop=_type_ _freq_)
      n=n mean=mean std=sd cv=cv_pct
      median=median min=min max=max;
run;

/* ② 对数尺度：GeoMean、GeoSD、GeoCV */
proc summary data=pk_demo nway;
  class trt tpt;
  var ln_aval;
  output out=logs(drop=_type_ _freq_)
      n=n_positive mean=mean_log std=sd_log;
run;

/* ③ 合并；如果某组存在0或负数，不悄悄改用正数子集 */
data summary_demo;
  merge arith logs;
  by trt tpt;
  if n>0 and n_positive=n then geomean=exp(mean_log);
  if n>=2 and n_positive=n then do;
    geosd  = exp(sd_log);
    geocv_pct = 100*sqrt(exp(sd_log**2)-1);
  end;
  /* n=1 时 SD / CV 通常不可计算 */
run;

/* ④ N（分析集人数）与 n（实际可分析浓度数）独立计算
   正式表中的 N 应从 ADSL + PK 分析集定义衍生；
   BLQ 数量应从保留 BLQ 状态的浓度记录计算。 */

为何要判断 n_positive=n？ 如果一组含零，而 SAS 对数步骤跳过零，直接计算会让 GeoMean 只针对「大于零的子集」，与算术统计的分析人数不同。是否这样做必须由方案定义，不能悄悄改变分析集。

注意：以上假设每个受试者×分析物×组别×时间点只对应一条用于统计的记录。正式输出的 n 是 PROC SUMMARY 对非缺失值的记录计数；若存在重复记录，应先按 Spec 整理，不能默认这就是去重受试者数。

05 · 浓度 Table 与 PK 参数 Table 不要混淆

PK 浓度汇总通常逐采样时点计算均值、变异、几何统计量，并可能包含 n of BLQ。PK 参数汇总则按 PARAMCD（如 CMAX、AUCLST、TMAX）计算分析参数的分布。

此前项目中，PK 参数表曾约定：ANL01FL='Y' 才纳入统计；N 为 PK 分析集人数，n 为非缺失参数数；Tmax 只展示 n、Median、Min、Max，其他统计量按项目规定显示 NC/NA。浓度表不能直接套用 Tmax 的特殊规则。

历史讨论还包括不同阶段 SAD/MAD/FE 的参数展示差异、有效数字位数，以及 PPCAT + PPTPTREF 的分组需求。这些属于项目级规则，不能作为 CDISC 强制要求。

06 · BLQ、NC 和真实 TFL 最容易出错的地方

BLQ（Below Limit of Quantification） 表示低于定量下限，不能直接理解成一个数值 0。若项目规定 BLQ=0，算术 Mean/SD 会包含该 0，但取对数无法直接纳入；若 BLQ 设缺失，则 n、均值等都会受影响。

既往 Shell 片段曾出现过按 BQL 数量 / 分母 > 2/3 标星并将部分统计量置为 NC 的做法。这是项目自定义展示规则，不是公认的统一阈值。 使用前需要核对真正的分母、BLQ 取值、是否有可测浓度以及脚注定义。

建议独立 QC：人群 N、有效 n、BLQ 数、n_positive、零值/缺失、分析物、给药组、时间点、单位、舍入位数、单个受试者重复记录。CV% 在 Mean=0、SD 在 n<2、几何 CV% 在对数样本不足时，不应强行计算一个数字。
