PROC FREQ：从频数到分类统计

分类统计最容易让人产生错觉：PROC FREQ 很快就给出 COUNT 和百分比，可它无法知道你打算报告的是“记录”还是“人”，也不知道 SAP 要用哪一个分母。理解这些差别，比背会 TABLES 选项重要。

百分比的分母从输出到表格什么时候需要检验

同一个格子，为什么会有三种百分比？

二维交叉表中，一个格子可以占全表多少、占本行多少，也可以占本列多少。PROC FREQ 并没有算错，它只是在回答不同的问题。真正要写进 TFL 的百分比，需要先读懂 SAP 的分析口径，再决定是否使用 ROW、COL 或自行计算。

proc freq data=sashelp.class;
  tables sex;
  tables sex*age / missing;
run;

回到数据核对：同一受试者多条记录时 FREQ 统计行数，而非自动去重的受试者数。

已经有了 COUNT，为什么还不能直接交付 n (%)？

OUT= 会给分类组合和计数，OUTPCT 会增加相应百分比；但数据中没出现的类别可能仍需要表壳补齐，而且同一受试者多条记录不应被无意当成多人。换句话说，PROC FREQ 负责算频数，TFL 程序还要负责分析人群、零行和显示规则。

proc freq data=sashelp.class noprint;
  tables sex*age / out=freq_cells outpct sparse;
run;

proc print data=freq_cells noobs;
  var sex age count percent pct_row pct_col;
run;

回到数据核对：OUTPCT 输出中的百分比字段（如 PCT_ROW、PCT_COL）口径不同；未出现的完整类别通常仍需用显式 shell 补齐。

什么时候频数表不再只是描述，而是在做推断？

当问题变成“组间分布是否不同”，才会进入卡方或精确检验。CHISQ 可以产生检验输出，EXACT 处理更适合某些稀疏列联表的情形，但选检验方法的理由来自设计与 SAP，而不是看哪个过程能跑出较小的 P 值。

ods output ChiSq=chisq_result;
proc freq data=sashelp.class;
  tables sex*age / chisq;
run;
ods output close;

回到数据核对：这个表的 age 有多个水平，不能把输出的所有 P 值都当作唯一正式 P 值；分析方法必须以 SAP 为准，若需 Fisher 可进一步查 EXACT 语句。

学习边界：代码使用 SASHELP 或自造示例，仅为官方语法参考与学习示范，未在本次对话的 SAS 环境执行；进入正式 TFL 前须按 SAP、Spec 和独立 QC 核对。
