PROC SQL：从查询到 TFL 数据汇总

一张 TFL 表看起来只是 n 和百分比，真正棘手的往往不是 SQL 语法，而是“这一行到底代表什么”。从查到记录，到数清受试者，再到发现 JOIN 让行数翻倍，问题是沿着数据一步步暴露的。

先把记录找对人数为什么会变JOIN 后发生了什么

为什么一条 SELECT 语句，可能已经改变了问题的含义？

如果只想看年龄在某个范围的受试者，SELECT、WHERE 和 ORDER BY 足够。但在临床项目里，一行可能是一次采血、一次不良事件，也可能是一个受试者。SQL 能找出符合条件的行，却不会替你决定分析单位；这一步想错，后面再精巧的汇总也会偏离目标。

proc sql;
  select name, sex, age
  from sashelp.class
  where age >= 13
  order by sex, age desc;
quit;

回到数据核对：先确认分析单位是一行记录还是一个受试者；SELECT DISTINCT 多列时，对整组列去重。

为什么 COUNT(*) 对了，受试者人数却不对？

想象一个受试者记录了三次相同类别的事件：COUNT(*) 会看到三行，但发生事件的受试者只有一人。于是需要 COUNT(DISTINCT USUBJID)；而表格里的百分比分母又是另一个问题，通常来自 ADSL 按分析集限定的人数，不能从事件表的行数顺手得到。

proc sql;
  create table total_n as
    select sex, count(distinct name) as big_n
    from sashelp.class group by sex;
  create table age_n as
    select sex, age, count(distinct name) as n
    from sashelp.class group by sex, age;
  create table summary as
    select a.*, b.big_n,
           100*a.n/b.big_n as pct format=6.1
    from age_n a left join total_n b
    on a.sex=b.sex;
quit;

回到数据核对：这个示例以 CLASS 的 name 当唯一键，仅演示统计机制；实际项目使用去重的 USUBJID，分母通常从 ADSL 对应人群计算。

明明只是 LEFT JOIN，结果为什么突然多出几行？

LEFT JOIN 并不会自动保证左表每行只对应右表一行。若右表连接键重复，一条左表记录就会被复制。先看连接键是否唯一，再决定是汇总右表、改用 EXISTS，还是本来就需要一对多的结构；HAVING 则用于检查汇总之后是否还有异常分组。

proc sql;
  /* 查看键是否重复 */
  select sex, count(*) as n
  from sashelp.class
  group by sex
  having calculated n > 1;

  /* 先把右表汇总成每个 sex 一行，再 join */
  create table key_unique as
  select sex, max(age) as maxage
  from sashelp.class group by sex;
  create table safe_join as
  select a.*, b.maxage
  from sashelp.class a
  left join key_unique b on a.sex=b.sex;
quit;

回到数据核对：JOIN 前后比较记录数，检查 JOIN 键唯一性与缺失匹配；需做存在性判断时优先考虑 EXISTS，避免无意义的 1:N 扩张。
