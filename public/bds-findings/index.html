01 / CONCEPT

先划清两个层级：SDTM Domain 不等于 BDS Domain

LB / EG / VS / PE 是 SDTM 中的 Findings 类 Domain。它们保存某个检查“在何时、采用什么条件、产生了什么结果”的标准化观察记录。BDS（Basic Data Structure）是 ADaM 的分析结构，常见数据集名称是 ADLB、ADEG、ADVS；只有分析确实需要时，才考虑建立 ADPE，并不存在所有 SDTM 域必须逐一映射为 ADaM 的要求。

核心变化：SDTM 一行描述“某项检查结果”；ADaM 一行描述“某位受试者、某个分析参数、某个分析时点的分析值及其上下文”。这个转换决定了后面所有编程工作。

LB实验室：生物学指标、单位与正常范围
EG心电图：电传导、复极与重复检查
VS生命体征：即时生理状态与测量条件
PE体格检查：体征与异常的临床归属
02 / DATA FLOW

临床业务怎样传递到分析结果？

CRF / EDC如何测、何时测、原始值与来源
→
SDTM FindingsLB / EG / VS / PE，保留观察事实
→
ADaM BDS结合 ADSL，定义分析参数/时间点/分析值
→
TFL均值、变化量、分类、阈值、Listing

从右往左理解更有效：统计师要求“给药后第 7 天 ALT 相对基线的变化”，就意味着 ADLB 需要一个可比较的 ALT PARAM、合理的分析访视 AVISIT、唯一或可筛选的分析记录、AVAL、BASE、CHG，以及可解释的基线选择规则。只复制 LB 数据是做不出这张表的。

原始实验室报告 → SDTM.LB (+ ADSL 给药信息) → ADLB → 变化量 Table / Shift Table / Listing

注意：原始/标准化结果并非总是数值；对 PE 定性结果和尿常规定性检查，分析可能使用字符值。ADaM 的分析需要决定结果表现方式，而不是把所有观察强制转换为数字。

03 / INTERNAL MODEL

BDS 的底层骨架：不是一堆字段，而是六个问题

WHO / SOURCESTUDYID、USUBJID、SRCDOM、SRCSEQ：是谁、追溯哪条记录？
WHATPARAMCD、PARAM、PARCATy：到底分析什么？
WHENADT / ADTM、AVISIT、AVISITN：哪次观测被分配给哪个分析时点？
VALUEAVAL / AVALC、BASE / BASEC、CHG、PCHG：分析值与比较基础是什么？
ELIGIBILITYSAFFL、ANL01FL、ABLFL：谁纳入？哪条记录参与？哪条是基线？
CONTEXT测量体位、样本类型、正常范围、DTYPE：结果能否同质比较？

AVAL 是数字分析值，AVALC 是字符分析值；二者可并存，但若在同一 PARAM 中共同赋值，必须符合 ADaM 对映射一致性的要求。AVALCATy 专用于对分析值分类，不能把它当成 AVALC 的随意替代。BASE 对应数值基线，BASEC 对应字符基线；CHG=AVAL−BASE，PCHG 通常为 100×CHG/BASE，但 BASE=0、缺失及业务不适用时不能硬算。

ABLFL 表示用于分析的基线记录；ANL01FL 是按具体分析用途定义的记录选择标志（名称是常见约定，含义必须写在 Spec 中）。二者不能混用。SRCDOM/SRCVAR/SRCSEQ 可帮助回溯来源；均值等多源派生记录不一定存在唯一 SRCSEQ，这时要靠来源组合和元数据描述算法。

04 / DOMAIN DEEP DIVE

四类检查：业务目的、数据结构与分析决策

选择一个领域，观察“为什么测 → SDTM 如何记 → ADaM 怎样分析 → QC 最容易错在哪里”。这四个流程的思考起点并不相同。

LB：数字只是表面，背后是“样本 + 检测方法 + 参考系统”

为什么要做？通过血常规、生化、凝血、尿常规等观察器官功能、代谢与潜在毒性。药物可能影响 ALT/AST、胆红素、肌酐、血红蛋白或电解质；临床上不仅关心结果大小，还关心是否超出正常范围、是否出现新的异常及其严重程度。

SDTM 的业务身份

LBTESTCD/LBTEST 决定检测项目；LBSPEC 是样本基质（血清、血浆、尿液等）；LBCAT 可区分 CHEMISTRY、HEMATOLOGY、URINALYSIS；LBMETHOD、LBNAM、LBDTC 说明检测方法、机构及采样时间。

结果与参考区间

LBORRES/LBORRESU 是原始结果和单位；LBSTRESC/LBSTRESN/LBSTRESU 为标准结果；LBSTNRLO/LBSTNRHI 是标准单位下参考区间。不要将原始单位的范围直接与标准单位的结果比较。

业务问题分析或 QC 需要作出的决定
ALT = 90 U/L 正常吗？不仅看 90，还要看该记录适用的 ULN / LLN、实验室和样本条件
有些结果是 NEGATIVE / POSITIVE属于定性结果，不可以简单用 INPUT 转成数值；可能使用 AVALC/分类分析
同一参数 U/L 和 µkat/L先确认单位可换算、转换因子及结果精度；避免不相容属性强合并
相对基线变化与 CTCAE前者比较 AVAL 与 BASE；后者按指定 CTCAE 版本、项目、基线状态及分级规则判断，不能一套倍数套所有项目
高值/低值都可能有毒性例如血细胞减少与某些高值异常属于不同方向；可能需要 ATOXGRL / ATOXGRH 等分析变量
虚构案例 受试者 S-001：ALT

给药前 ALT=30 U/L，Day 7 ALT=90 U/L，假定样本与方法可比较：AVAL=90、BASE=30、CHG=60、PCHG=200。但不能仅凭这四个数给出 CTCAE 等级：还要看相应版本的 ALT 规则、正常值上限、基线状态等。即使数值异常，也不能自动转化为 AE。

最常见的业务事故：不同中心不同 ULN；把尿蛋白定性 +/++ 做成连续数值；把不兼容单位机械换算；忽略标本状态（溶血/脂血）；未处理多次抽血导致同一时间窗重复统计；混淆高低毒性方向。

EG：检查的是心脏电活动，不只是“心率”

为什么要做？十二导联心电图记录心脏电活动，识别心律、传导及复极的变化。对某些新药，尤其要看 QT/QTc 是否延长。QTc 是心率校正后的 QT 间期，QTcF 使用 Fridericia 校正，常见表达式为 QTcF(ms)=QT(ms)/RR(s)^(1/3)；前提是单位和算法正确。

SDTM 的三层粒度

一个观察参数（如 PR、QRS、QT、QTc、总判读）可以来自一次心电图；一次时点可能安排多次重复检查（replicate）；某次检查内部又可以按心搏（beat）记录。EGREPNUM 区分重复检查，EGBEATNO 区分心搏，二者不是一个概念。

12 导联 ≠ 重复 12 次

EGMETHOD 可记录 12-LEAD STANDARD；EGLEAD 记录用于某项测量的导联。12 个导联表示观察心脏电活动的不同视角，不等于 12 次独立测量，更不能因此分母乘以 12。

关注点SP 必须先问
QTcF / QTcB来自设备还是由 QT/RR 计算？选哪种心率校正？各自 PARAM 是否区分？
三次心电图同一计划时间点的 replicate 吗？需要算均值，还是保留单次用于分析？
基线 ECG给药前一次还是多次均值？基线与治疗后采用相同的汇总规则吗？
异常判读定性结果 NORMAL/ABNORMAL 与数值 QTc 应分成不同分析参数
C-QTcECG 采集时间能否与 PK 实际采样时间精确对应？有无时差/窗口定义？
虚构案例 Day 1，给药后 2 小时同一时点的三次 QTcF

468、474、471 ms。假定 SAP 规定同一时点取算术均值，分析值是 471 ms。需要保留三次源记录以及“均值如何得到”的追溯信息；不能把 3 次结果都标记成唯一的 ANL01FL=Y 再计算该时点受试者统计。若三次并非同一分析时点，也不能擅自求均值。

最常见的业务事故：先算均值再校正与先校正再算均值混淆；QT/QTcB/QTcF混用；分钟与毫秒混用；同一检查多行被当成多个受试者；精确采样时点丢失，导致 C-QTc 不可用。

VS：同样是一个血压值，体位不同就可能不是同一个问题

为什么要做？血压、脉搏、体温、呼吸频率、身高、体重、BMI 可反映药物对循环、呼吸与全身状态的影响。它往往频次高、贴近给药时间，数值看起来简单，但测量条件的影响特别大。

参数与测量环境

VSTESTCD 可区分 SYSBP、DIABP、PULSE、TEMP、WEIGHT、BMI 等；VSPOS 区分坐位、卧位、立位；VSLOC/VSLAT 可记录手臂与左右侧等相关条件；VSDTC/VSTPT 描述采集时间和计划时点。

为什么要给出这些细节

坐位血压与立位血压涉及不同的生理状态；一组立位-卧位对照可用于体位相关的临床评价，但前提是方案事先定义。脉搏 PULSE 与 ECG 心率 HR 即便数值相近，采集技术与生理意义也不完全相同。

业务决定SP 如何处理
收缩压与舒张压分别作为分析参数，不能简单拼成单一连续数值
卧位/坐位/立位作为参数定义或分析分组的一部分；不可跨条件无理由混合
给药前测三次血压核对是否取最后一次、均值或其他规定值；看对应时间点与 replicate 信息
体重 / BMIBMI 可以由体重和身高衍生，但须明确单位、测量日期及来源；并非 SDTM 任意两条值直接拼算
异常值与生命体征临床显著性门槛按方案，数值异常不自动等于已发生 AE
虚构案例 坐位收缩压

基线 132 mmHg，Day 7 坐位收缩压 118 mmHg：CHG = 118−132 = −14 mmHg。如果 Day 7 另有立位收缩压 105 mmHg，不能无条件拿它替代坐位分析值。项目若比较体位性变化，应定义新的计算规则和分析时点。

最常见的业务事故：体位混用；左右臂混用；重复测量与访视映射不一致；在同一次生命体征内把脉搏与 ECG HR 当同一 PARAM；BMI 计算时将 cm 当 m。

PE：最需要理解业务边界的一个 Domain

为什么要做？体格检查通过视、触、叩、听评估身体系统或发现体征异常。它与实验室检查最大差别是结果经常为定性或叙述性：“NORMAL”“皮肤见皮疹”“查体未做”，不是统一可运算的数值。

SDTMIG v3.4 的重要特殊说明：在与 CDASH Best Practice 对齐的采集模式中，PE Domain 可以不使用；PR 记录检查已执行及日期，筛选/基线已存在的异常可进入 MH，基线后新发或加重异常依据事实与 CRF 设计进入 AE 或 CE。这不是说 SP 可以自行把 PE 异常“制造”成 AE；应遵循医学审阅和数据采集流程。

采用 PE 域时

PETESTCD/PETEST 表示检查的身体系统；PEORRES 为原始异常描述，正常时可为 NORMAL；PESTRESC 是字符标准结果；PESTAT=NOT DONE 表示没有进行。来源记录粒度通常是“受试者 × 访视 × 身体系统/异常”。

是否要建立 ADPE

只有当 TFL/SAP 需要分类分析、正常→异常变化、某些预定义体征分析且 SDTM 不足以直接支持时，才考虑 BDS 形式的 ADPE。可使用 AVALC 和 BASEC；不能凭一个 NORMAL/ABNORMAL 结果硬设 AVAL 并做 CHG。

临床事实不能误判成数据讨论重点
皮肤检查 NORMAL“没有采集数据”这是一个已完成的正常检查结果
皮肤检查 NOT DONENORMAL这是未完成，需要检查原因是否采集
筛选期发现既存皮疹自动产生给药后 AE通常先判断既往已存在状态与 MH 采集流程
给药后新发皮疹一条单纯的 PE 数值异常需要核实 AE/CE 记录与临床判断
虚构案例 皮肤检查：基线 NORMAL → Day 7 ABNORMAL

若方案要求体检 Shift Table，可在适当的 ADaM 分类分析结构中设置 BASEC=NORMAL、AVALC=ABNORMAL，统计受试者从正常转异常的人数。但是否构成 AE、何时起始及严重程度均不能由这两个字符串自动判定。

最常见的业务事故：把正常和未做混淆；把体格检查结论、异常体征、AE 三者强行视为同一事实；在不需要统计分析时徒增 ADPE；把不同身体系统强行聚合成一个定量 PARAM。

05 / PARAM DESIGN

为什么不能把 --TESTCD 直接一对一复制成 PARAMCD？

ADaM 的 PARAM 必须唯一刻画一类可直接比较的分析值。SDTM 的 --TESTCD 有时需要结合样本、体位、方法、导联或衍生规则才能明确一个分析参数。

源数据观察缺少哪个限定就可能产生误分析ADaM 设计思路
LB：GLUC血清/血浆/尿液、空腹状态、单位与检测方法必要时将样本/条件纳入 PARAM 定义或分析分层
EG：QT / QTc校正方法、单次 vs 均值、导联或时间点区分 QTcB / QTcF；均值衍生规则透明
VS：SYSBPSITTING / SUPINE / STANDING、测量部位必要时分别建立分析参数或限定分析集
PE：SKIN哪个身体系统、正常/异常及异常文本考虑字符型参数，避免强制赋值无效数字

重要的 CDISC 约束：在同一 BDS 数据集中 PARAM 与 PARAMCD 必须一一对应，PARAMCD 不超过 8 个字符。表中分析参数示意不是建议的官方编码值；真正的命名、标签、单位与派生规则应先在项目 Spec 中确定，并核对适用的 CT。

06 / TIME & BASELINE

基线、分析访视、重复测量：为什么经常是 BDS 的核心工作量？

1. 找到事实发生时间

LB 看标本采集时间，EG 看心电图采集时间，VS 看实际测量时间，PE 看体检时间；原始日期只有“日”时，不能擅自补成某个精确时刻后用于给药前后判断。

2. 定义分析可比较的时间窗

实际 VISIT 可能与计划 AVISIT 不同。先有窗口规则，再谈某条记录是否进入 Day 1、Day 7；窗口重叠、计划外采集、多次记录必须有优先级。

3. 决定基线

通常与首次给药前相关，但并不总是“最后一个给药前数值”；EG 可能取多次基线均值，LB/VS 可能按不同条件分别选取。由 SAP/Spec 决定；衍生的均值基线应保留可追溯性。

4. 决定分析记录

通过项目定义的 ANL01FL 或等效逻辑，选择主要统计所需记录。保留多个源记录以支持 QC，不等于让它们全部计入同一 TFL 单元格。

5. 形成 BASE 与变化量

同一受试者、同一分析参数、同一定义基线（必要时含 BASETYPE）才可以复制基线。连续变量算 CHG/PCHG；分类变量可能做 BASEC→AVALC Shift。

一句话判断：ADaM 的工作不是“再保存一份 SDTM”；它是把“在不同时间、条件下采集的观察”变成“能够按某个规则比较的分析对象”。

07 / SPEC DESIGN

由 TFL 倒推四类分析数据集

TFL 要求ADaM 至少需要什么容易遗漏的业务规则
各访视均值、SD、范围AVAL、PARAM、AVISIT、TRT、分析集/分析标志受试者-参数-访视是否唯一？重复测量选择规则是什么？
较基线变化/百分比变化ABLFL、BASE、CHG、PCHG（按需）基线定义、缺失与零分母、特殊均值基线
正常值或 CTCAE Shift适用的范围/毒性变量与基线分类；数值、单位、上下限CTCAE 版本、基线依赖规则、双向异常、未评级与缺失
QTc 阈值或 ΔQTc 阈值人数QTc 参数、BASE、CHG、最大值/分析标志、阈值指标单次/均值与时间窗的判定、阈值等号方向、受试者去重
体格检查正常→异常字符型分析值 AVALC/BASEC，身体系统，分析访视NORMAL/ABNORMAL/NOT DONE 不可混淆；PE 域是否存在

某些 Listing 只需要从 SDTM 直接生成，不一定需要相应 ADaM；不要因为已有 SDTM 域就默认创建一个内容完全重复的分析数据集。

08 / SAS EXAMPLE

一个小例子：把“给药前最后一次非缺失值”变成 BASE

为了聚焦 BDS 原理，以下使用完全虚构的连续结果。设首次给药日期为 2026-01-10，事先排除不满足参数/测量条件的记录，并假定时间精度仅到日期，所有候选基线都发生在 1 月 10 日之前。

/* 教学示例：未在实际项目 SAS 环境运行验证。
   项目应按 SAP/Spec 使用真实 TRTSDTM 和完整 ADTM。 */
data src;
  length usubjid $8 paramcd $8;
  input usubjid $ paramcd $ adt :date9. aval;
  format adt date9.;
datalines;
S001 ALT 01JAN2026 32
S001 ALT 09JAN2026 30
S001 ALT 17JAN2026 90
S002 ALT 08JAN2026 41
S002 ALT 17JAN2026 38
;
run;

/* 每个受试者每个参数：最后一个给药前非缺失结果 */
proc sort
  data=src(where=(adt < '10JAN2026'd and not missing(aval)))
  out=bl_cand;
  by usubjid paramcd descending adt;
run;

data bl;
  set bl_cand;
  by usubjid paramcd descending adt;
  if first.paramcd;
  base=aval;
  keep usubjid paramcd base;
run;

/* 简化的 BASE/CHG 示范；不代表完整 ADaM BDS */
proc sql;
  create table demo as
  select a.*, b.base,
         case when not missing(a.aval) and not missing(b.base)
              then a.aval-b.base else . end as chg
  from src as a
  left join bl as b
    on a.usubjid=b.usubjid
   and a.paramcd=b.paramcd;
quit;

这段代码刻意没有直接标记 ABLFL / ANL01FL，也没有计算 PCHG：完整 ADaM 必须先处理并列时间、确切给药时刻、可能的不同基线定义、记录可追溯性以及每个分析访视的优先规则。不能把这个日期示范直接当生产程序。

如何将它提升为项目级 ADaM？

第一步接入 ADSL 的真实给药信息及分析集标志；第二步完成标准参数映射和单位转换；第三步完成时间窗、基线与重复测量逻辑；第四步形成 PARAM/AVAL/BASE/CHG/ABLFL/ANL01FL 及源记录追溯；最后以独立 QC 程序验证 Table/Listing。最难的是第一到第三步的业务约定，不是 SAS 语法。

09 / QUALITY CONTROL

写 Spec 和 QC 时最实用的决策清单

01 / 数据来源和粒度：一行究竟代表什么？

确认 CRF/EDC 采集表、SDTM Domain、每个参数的来源、观察层级、是否存在重复检查或衍生记录；EG 区分心搏/replicate/时点，PE 区分身体系统/异常描述，LB 区分标本与检查项目。

02 / PARAM：是否真正同质、可比较？

检查不同样本基质、方法、单位、体位、导联、QTc校正方法、定量/定性的差异；不能因 TESTCD 一样就默认参数可以混合分析。

03 / 结果及单位：有没有不可逆的信息损失？

原始值和标准化值、定量/定性、检测下限、异常文本、正常范围等必须合理保留；LAB 的参考区间也要保证单位一致，PDW 的百分比与 fL 等不同物理量不能仅因名称相似就转换。

04 / 时间：筛选期、给药前和治疗后是否被准确区分？

优先关注实际采样时间、给药时刻、时区、时间精度、重叠窗口及计划外访视。不要让一个补全的时间自动决定治疗前后归属。

05 / 基线及分析标志：能否重建被选中记录？

对每个受试者×参数×基线定义检查 ABLFL；对每个需要唯一观察的分析单元核查 ANL01FL。BASE/BASEC 必须对应正确的基线记录，异常或多次记录须有明确处理。

06 / 临床规则：异常是否被误当成事件？

LB 毒性等级不等于 AE 严重程度；EG 异常判读不自动等于 AE；VS 超阈值不自动等于 AE；PE 异常须根据来源和临床流程确定是否关联 MH/AE/CE。

07 / 输出：表格人数和记录数有没有混用？

计算 N、n、任意一次阈值超出、Shift 和最大等级时，确认分母与去重单位；一人三次 ECG 不是三个人。区分缺失、未做、未分级、不满足分析条件。

08 / 可追溯：独立程序能否从 SDTM 复算？

核查源记录标识、原始/标准化单位、取值算法、DTYPE、ADRG/Define 中的派生说明；不要让主程序与 QC 程序复制同一错误的业务假设。

10 / SELF CHECK

五个最值得问自己的业务问题

  1. 同一受试者一个访视有三次心电图，是否需要三个分析样本？

    不一定。三次是观察记录；是否先取均值、保留原始三次、哪个进入主要 TFL 取决于 SAP/Spec。受试者计数不能因此变成 3。

  2. 两个 LB 记录 ALT 都是 90，可以直接认为异常程度一致吗？

    不可以。先判断单位、样本/检测体系、适用的正常上限及 CTCAE 规则。相同数值未必对应相同 ULN 倍数或毒性分级。

  3. VS 的 PULSE 是否可以直接取代 EG 的 HR？

    不能默认替代。采集方法不同，某些心律情况下二者可能不同。分析参数应由检测定义和 SAP 确定。

  4. 体检结果为 NOT DONE，能否当作 NORMAL 参与 Shift？

    不可以。未做与正常是不同的临床信息，未做通常不能证明没有异常。

  5. 一项研究有 PE Domain，是否必须生成 ADPE？

    不必须。若 SDTM 足以支持 Listing 或无 PE 相关统计分析，可以不建；采用 CDASH Best Practice 的研究甚至可能没有 PE Domain。
