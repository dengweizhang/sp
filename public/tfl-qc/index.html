PROC COMPARE 通过以后，最终 RTF 还要查什么？

两份统计数据集逐值一致，最终 RTF 仍可能把 A 组和 B 组的数字摆反。下面用一张模拟 TEAE 表定位问题。

先从一格数据找出差错在哪层

某张 TEAE 表的生产和独立 QC 数据集对比一致。分析结果是 A 组 3 人中 2 人发生 TEAE、B 组 2 人中 1 人发生 TEAE。打开 RTF 后，表头和每组 Big N 都对，但正文数字与表头对不上。

至少一项 TEAEA 组（N=3）B 组（N=2）
期待从报表读到2 (66.7)1 (50.0)
实际从报表读到1 (50.0)2 (66.7)

这个模拟案例的错误发生在报表层。PROC REPORT 输出 B 列在前、A 列在后，表头却按 A、B 的次序绑定。复核时把同一格追到三个对象：独立算出的数字、报表程序里的变量与表头映射、最终文件里的实际位置。

用 COL_A、COL_B 代表来源固定的两列，先核对它们在 COLUMN 中的顺序，再核对各自的 DEFINE 和 Big N 来源。修复后重新生成 RTF，用表头标识去核对数值，保留一条 A/B 数值不同的回归用例。若两组数字刚好相同，组别对调可能在单行里看不出来。

分析数据和统计结果分析人群、去重键、分母、百分比和边界记录。按实际比较粒度确认 ID 唯一、两侧键集合与变量一致，并查看 PROC COMPARE 输出。
已经生成的 RTF表号、分析人群、分组列顺序、Big N、正文、脚注和分页。项目允许时，可用脚本检查能可靠解析的内容，并在最终文档里核对版面。
这批交付文件按清单核对应有文件、实际生成时间或本轮运行记录、相关日志和 QC 状态。如果数据刚刷新，确认交付件使用本轮输入及程序。

旧版和新版的差异可作为回归线索。比如这次只改了亚组逻辑，先列出预期受影响的表和行，再查看有没有意外变化。遇到文件缺失、无法解析或行列无法配对时，记录为待核对，保存对应表号、页码或行列位置。

怎么把发现写得让同事能直接复核？

一条够用的记录如下：

模拟 TEAE 表，「至少一项 TEAE」行。A 组列显示 1 (50.0)，独立计算预期 2 (66.7)。B 组呈相反差异，统计数据集对比一致。检查报表列和表头映射，修复后重出并按组核对这一行。

这条记录写清了位置、实际值、预期值和复核路径。若一个映射错误影响多张表，可按共同报表模板追查，再在各份最终文件里确认结果。
