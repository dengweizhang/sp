NOTE 001 · 2026-11-20 · PROC FORMAT / TFL / n (%)

百分比 PICTURE 格式：为什么 COUNT 与括号之间多出空格？

真实问题

TFL 宏将字符型 COUNT 和 PCT 拼为 n (%)。例如某些行显示为 64 (100)、63 ( 49.6)、6 ( 9.5)。想统一为：COUNT 与左括号之间只保留一个空格；括号内部保留原设计的位数对齐。

原来的拼接表达式

compress(COUNT)||put(input(compress(PCT),BEST.),pctfmt.)

问题不在比例计算，而在 PUT(...,pctfmt.) 生成的字符结果可能带有左侧填充空格；运算符 || 原样保留这部分空格。COMPRESS(COUNT) 只处理 COUNT 一侧，不会清掉 PUT 返回值左边的空格。

最终修复（本次实测已解决）

catx(' ',
    compress(COUNT),
    put(input(compress(PCT),BEST.),pctfmt.)
)

CATX(' ', a, b) 会先去掉每个参数的首尾空格，再用一个空格连接非空参数；它不会去掉括号内已有的空格。这里仍沿用原 pctfmt.，不需要额外用 TRANWRD() 硬匹配两个空格。

输入示例原格式中关注的字符最终目标
COUNT=6，PCT=9.5括号内部两个空格6 ( 9.5)
COUNT=63，PCT=49.6括号内部一个空格63 ( 49.6)
COUNT=64，PCT=100格式可能在括号外补空格64 (100)
COUNT=1，PCT=0零百分比映射为空格1

小结：格式负责百分比怎么显示，拼接函数负责字段之间的间隔。把这两个责任分开，才能避免反复修改格式模板。

基础 01 · PROC FORMAT 到底在做什么？

Format 只决定值如何显示，不会改变原变量的存储值。 相同的数值可以输出为数字、文字标签、日期或自定义模板。PROC FORMAT 是创建自定义格式/输入格式的过程，常用三种语句：

语句作用典型使用
VALUE数值 → 显示文本agegrp. 年龄分层
VALUE $name字符 → 显示文本$yn. Y/N 显示 Yes/No
PICTURE数值 → 按数字模板显示百分比、金额、括号、零位填充
INVALUE字符输入 → 数值将 Yes/No 读取成 1/0
proc format;
    value agegrp low-<18 = 'Under 18'
                 18-<65 = '18–64'
                 65-high = '65+';
    value $yn 'Y'='Yes' 'N'='No' other='Unknown';
    invalue ynnum 'Yes'=1 'No'=0 other=.;
run;

data demo;
    age=45; flag='Y'; raw='12.5';
    age_label = put(age,agegrp.);   /* numeric -> character */
    flag_label = put(flag,$yn.);   /* character -> character */
    pct_num = input(raw,best.);   /* character -> numeric */
    yn = input('Yes',ynnum.);     /* character -> numeric via INVALUE */
run;

读懂本次 pctfmt. 的每一行

proc format;
    picture pctfmt (round)
        0              = " "       (noedit)
        0<-<0.1        = "(<0.1)"  (noedit)
        0.1-<9.95      = "09.9)"   (prefix="(  ")
        9.95-<99.95    = "00.0)"   (prefix="( ")
        99.95-high     = "(100)"  (noedit);
run;
写法含义
PICTURE pctfmt定义数值显示格式，使用时写 pctfmt.（有句点）
0<-<0.1严格大于 0、严格小于 0.1；边界是否包含由 < 控制
ROUND根据模板与乘数，在格式化数字时四舍五入；不是修改原始变量
09.9) / 00.0)数值编辑模板；零是数字占位符，末尾 ) 是文字
PREFIX="( "在有效数字前设置前缀，包括设计中的括号和空格
NOEDIT让模板中的数字作为固定文字显示，例如 (100)；但结果仍可能受到格式总宽度对齐影响

重要边界：上面的 99.95-high = "(100)" (noedit) 会将所有大于等于 99.95 的输入显示为 (100)，包括大于 100 的值。这只有在业务上保证百分比最大为 100、并认可该显示约定时才适用。若百分比可能超过 100，应单独重设区间与模板，不要直接沿用该分支。

基础 02 · INPUT() 与 PUT() 如何区分？

对当前宏，记住这一条数据流最有用：

字符型 PCT → INPUT() → 数值百分比 → PUT() → 可显示的字符结果 → CATX() → n (%)
函数接收返回典型示例
INPUT(source,informat.)字符文本 + 输入格式（informat）通常为数值，也可以是字符input('12.5',best.) → 数值 12.5
PUT(source,format.)一个值 + 显示格式（format）字符put(12.5,pctfmt.) → 格式化字符串
FORMAT var fmt.;变量 + 显示格式仍为原变量类型format age agegrp.; 只修改显示

逐层解剖原表达式

compress(PCT)                        /* 删除 PCT 内的空格 */
input(compress(PCT),BEST.)           /* 字符 '12.5' -> 数值 12.5 */
put(input(compress(PCT),BEST.),pctfmt.) /* 数值 -> 格式化字符 */
compress(COUNT)||...                 /* COUNT 与格式化字符直接相连 */

两个容易混淆的地方：INPUT 的第二个参数是 informat；PUT 的第二个参数是 format。BEST. 在上述 INPUT 调用中表示读取普通数值文本的输入格式，pctfmt. 则是我们定义的数值输出格式。PUT 返回字符不代表原数值被修改。

如果 PCT 原本就是数值型，不需要先 INPUT；如果 COUNT 原本是数值型，建议先用 PUT(COUNT,BEST.) 转为字符，避免隐式转换。

/* COUNT / PCT 都是字符：沿用本篇处理 */
result = catx(' ',compress(COUNT),put(input(compress(PCT),best.),pctfmt.));

/* 如果 COUNT / PCT 本身均为数值型：不要做多余的 INPUT 转换 */
result = catx(' ',strip(put(COUNT,best.)),put(PCT,pctfmt.));

基础 03 · ||、CATX、STRIP、COMPRESS、TRANWRD 怎么选？

写法主要行为何时用
a || b直接拼接；原有前后空格可能保留确实需要原始空格时
CATX(' ',a,b)去掉各参数首尾空格，再插入一个分隔空格本次 COUNT + 百分比 首选
STRIP(x)删除首尾空格，不改变内部空格清理单个字段首尾
COMPRESS(x)默认删除所有空格，也会删内部空格清理无须保留内部空格的原始字符串
TRANWRD(x,a,b)按固定子串替换有明确固定文本需替换；不宜依赖空格个数
QUOTE(x)给文本加引号，方便在 Log 中辨认前导空格排查显示问题

CATX() 会去掉字符串首尾空格，但保留内部空格，因此 ( 12.5) 的对齐设计不受影响。与此不同，对格式化百分比再次使用 COMPRESS() 会把括号内部有意保留的空格也清除。

完整可运行的 SAS 测试代码

复制到 SAS 直接执行，模拟字符型 COUNT、PCT，并且将原表达式与修复后的结果并排输出。为检查前导空格，先生成 raw_visible、final_visible 变量，再通过 PUTLOG 输出，不在 PUTLOG 中直接嵌套函数调用。

/* NOTE 001: 使用与实际 TFL 宏相同的字段类型与表达式 */
proc format;
    picture pctfmt (round)
        0              = " "       (noedit)
        0<-<0.1        = "(<0.1)"  (noedit)
        0.1-<9.95      = "09.9)"   (prefix="(  ")
        9.95-<99.95    = "00.0)"   (prefix="( ")
        99.95-high     = "(100)"  (noedit);
run;

data pct_cases;
    length COUNT PCT $12;
    input COUNT $ PCT $;
    datalines;
1 0
2 0.05
3 0.1
4 5
5 9.95
6 12.5
7 50.4
8 99.95
9 100
;
run;

data pct_check;
    set pct_cases;
    length pct_show $20 result_raw result_final $60
           raw_visible final_visible $120;

    /* INPUT：PCT 字符 -> 数值；PUT：数值 -> 格式化字符 */
    pct_show = put(input(compress(PCT),best.),pctfmt.);

    /* 原表达式：|| 保留 PUT 的前导空格 */
    result_raw = compress(COUNT)||
                 put(input(compress(PCT),best.),pctfmt.);

    /* 推荐：只留下 COUNT 与括号之间一个分隔空格 */
    result_final = catx(' ',compress(COUNT),
                   put(input(compress(PCT),best.),pctfmt.));

    /* QUOTE 可看清空格；PUTLOG 输出变量而不是函数调用 */
    raw_visible   = quote(trim(result_raw));
    final_visible = quote(trim(result_final));
    putlog COUNT= PCT= raw_visible= final_visible=;
run;

proc print data=pct_check noobs;
    var COUNT PCT raw_visible final_visible;
run;

重点查看 final_visible 引号内，COUNT 与 ( 之间是否只有一个空格。测试覆盖 0、0.05、9.95、12.5、50.4、99.95、100 等边界；它不代表真实临床项目的百分比校验规则。

边界与 QC 清单

  • 0% 隐藏：本次格式把数值 0 映射为空格，因此 CATX() 拼接后只显示 COUNT；需要显示 (0) 的项目应另定规则。
  • 不等于 100 的上界：本次 99.95-high 是固定字符串映射，不会保留超出 100 的真实值；百分比在某些计算场景可能超过 100，必须先定义业务范围。
  • 缺失值：字符型 PCT 为空或非数值文本时，INPUT(...,BEST.) 可能返回缺失并产生无效数据提示；生产宏应检查原值、分母与缺失规则。
  • 比例的尺度：若 PCT 是 0.125 而想显示 12.5%，需要确认上游是否已经乘以 100；本格式不自动把比例乘 100。
  • 固定宽度与对齐：去掉外部填充空格适合 n (%) 输出；若 PROC REPORT 依赖整列宽度对齐，还需检查列宽、字体和 RTF/PDF 效果。
  • 变量类型：确认 COUNT 与 PCT 是字符还是数值；不要仅靠自动类型转换。
