药物上市前的监管递交：从 IND 到 NDA / BLA

弄懂申办方如何将多项研究、标准化数据、报告及质量证据组织成监管可审查的上市申请，并明确 SP 在其中的职责。

先区分：临床研究递交 ≠ 药物上市许可申请

临床研发期间，企业可能提交 IND / CTA、方案修订、年度报告、安全性信息与阶段沟通资料；拟获批上市时，才提交 NDA / BLA / MAA 等申请。SP 所产出的 SDTM、ADaM、TFL、Define 与相应说明，是上市申报中可核查的临床研究证据之一，不等于整个申报材料。

本篇以美国 FDA 常见 NDA/BLA 流程为主，辅以中国 NMPA/CDE 和 ICH 的要求。递交规则会更新，文中有明确时间节点的内容均标注官方来源与日期。

1. 临床试验结束，为什么还不能直接上市？

一项Ⅲ期研究结果阳性不等于药物获批。监管机构还要从整个研发证据中评价质量（CMC）、非临床安全性、临床疗效、安全性、风险管理和拟定说明书是否充分支持特定适应症、剂量和人群。

有些产品可能通过不同阶段/研究方案完成证据积累，上市申报可能同时整合多个临床试验、临床药理研究、长期安全性以及制造与质量控制资料。“数据库锁库”“CSR 完成”“eCTD 提交成功”“监管批准”是不同里程碑。

研发阶段发现 / 非临床药效、毒理、CMC
→
进入临床IND / CTA临床研究许可或申报
→
临床证据Ⅰ–Ⅲ期等方案、数据、CSR
→
申请上市NDA / BLA / MAACTD / eCTD 资料
→
监管结论批准 / 补充 / 不批准上市后持续监管

流程是高度简化的概念图。不同产品与监管路径存在并行、补充和特殊安排，不表示每一种药都必须严格按完全相同的阶段推进。

2. 最容易混淆的递交缩写

术语用途不能混淆
IND
Investigational New Drug		美国用于临床研究阶段的相关研究性新药申请不是 NDA 上市批准；IND 不表示药物已上市
CTA
Clinical Trial Application		多个法域用于临床试验授权/申报的概念地区的受理程序不同，不能把所有 CTA 当成 FDA IND
NDA
New Drug Application		美国新药上市申请（通常化学药等，按适用法规）与仿制药 ANDA 或生物制品 BLA 区别
BLA
Biologics License Application		美国适用生物制品许可的上市申请不是所有生物制品都走与化学药相同的路径
ANDA
Abbreviated NDA		美国仿制药简略新药申请一般依赖参比制剂与等效性等不同证据路径
MAA
Marketing Authorisation Application		欧盟等地区的上市许可申请用语不直接等同于美国 NDA 的法律分类
NMPA / CDE中国国家药监局 / 药审中心中国常称药品上市许可申请、药品注册申请
CTD / eCTD通用技术文档结构 / 电子化技术递交标准是提交资料的组织方式，不是另一种药物许可证
CSRClinical Study Report，临床研究报告是某项研究的正式报告，不等于整个 NDA/BLA

就 SP 而言，常听到的“这项目是注册项目”“要递交 FDA”，通常意味着对数据标准版本、可追溯性、Define-XML、Reviewer Guides、程序和跨研究一致性有更明确的要求，但具体递交范围仍取决于申报计划与主管监管机构。

3. 典型药物从开发到上市申请如何推进？

Step 01早期规划非临床、临床开发计划、CMC、监管沟通
Step 02试验实施Protocol、SAP、CRF、数据标准、随机、给药与随访
Step 03数据锁定 / 统计分析Database Lock、SDTM/ADaM、TFL、QC、盲态控制
Step 04申报材料汇总CSR、整合分析、CTD 文档、电子数据包与验证
Step 05递交与审评申报、技术/受理核查、专业审评、问询回复与决定

SP 在什么阶段就需要考虑递交？

不是 Database Lock 之后才想起标准。FDA 建议在药物研发较早阶段制定 Study Data Standardization Plan（SDSP），在 IND 期间及上市前沟通中持续更新。方案、CRF、SDTM Spec、ADaM Spec、分析程序都应尽可能提前考虑后续可追溯性和版本兼容问题。

申报时常见“Pre-NDA / Pre-BLA Meeting”用于与 FDA 沟通递交内容、关键科学问题和技术准备，但会议机制和适用条件应以产品/具体监管部门为准。

4. CTD / eCTD 五个模块，各放什么？

ICH CTD 由五个模块构成。Module 1 是地区特定内容，Module 2–5 是跨 ICH 地区尽量协调的共同结构。电子化递交 eCTD 在此内容结构上增加电子骨架、元数据、生命周期操作等技术要求。

模块内容SP 相关性
M1
Regional		行政文件、区域特定表格、标签等多由注册事务负责；SP 可能配合核对申报标记/研究目录
M2
Summaries		质量、非临床、临床概览与总结汇总分析结果可能被引用，需要跨报告数据一致
M3
Quality / CMC		药学研究、制造工艺、质量控制、稳定性主要由 CMC/质量部门负责，不是 SP 日常主业
M4
Nonclinical		非临床研究报告；适用时相关标准化研究数据SEND 数据通常由非临床相关团队准备
M5
Clinical		临床研究报告、临床研究数据与相关支持材料SDTM、ADaM、Define-XML、cSDRG、ADRG、分析程序、CSR TFL 等

不要理解成“把 SAS 数据集放进 M5 就算 eCTD”。除了数据内容，还需满足 FDA 支持的格式、文件组织、相应元数据和技术验证。不同监管机构及 eCTD 版本对电子包结构可能有具体差异。

5. 单项临床研究：SP 最常见的递交数据包

交付件用途重点校验
SDTM XPT标准化临床试验表格数据，支持源数据审阅域与变量结构、CT、时间、TS、数据准确性、支持格式
ADaM XPT反映主要统计分析所使用数据，支持结果复核分析集、参数、分析标志、推导、缺失处理、追溯
Define-XML描述数据集、变量、值级元数据、方法和来源元数据与实际 XPT 一致、XML 可解析、链接完整
aCRF将 CRF 采集位置映射至 SDTM 数据变量注释与数据映射一致，未提交数据有解释
cSDRGStudy Data Reviewer’s Guide，给审评者解释临床表格数据的特殊处理数据映射例外、SDTM 已知问题、版本、异常
ADRGAnalysis Data Reviewer’s Guide，解释 ADaM 数据、分析假设及一致性问题关键派生与填补、支持数据、模型、软件与已知问题
程序源代码可复现 ADaM 和关键有效性分析的程序版本、运行依赖、路径、日志、与提交输出一致
CSR、TFL、SAP临床报告及其分析方法和表格结果结果对齐、脚注与样本数、版本、分析说明
特别关注 2026 年 FDA《Study Data Technical Conformance Guide》

2026 年 10 月版 §4.1.2.8–4.1.2.10 强调：部分日期仅对 SAP 分析所需日期进行填补并使用对应 ADaM 标志；插补应通过 define.xml 和 ADRG 解释；应提供生成 ADaM、主要/次要疗效 Tables/Figures 的相关源代码，以及必要的软件版本和环境说明。

这说明递交不是“XPT 能打开”就结束了。你自己开发的 XPT 查看工具能解决数据查看，但申报还要解决一致性、元数据、追溯、解释和验证。

SDTM 与 ADaM 为什么都需要？

SDTM 主要整理成监管可理解的标准研究数据；ADaM 组织支撑统计分析和审评复算的数据。FDA 特别关注数据是否可从研究数据追溯到分析及报告结果，若源数据到分析数据的关联缺失，可能增加审评困难。

6. 一个 SP 真正需要负责哪些步骤？

① 标准与版本核查锁定 FDA Data Standards Catalog 支持版本、SDTMIG/ADaMIG/CT、Define-XML 版本与项目约定
② 数据集准备生成并独立 QC SDTM / ADaM，检验 XPT 导出和重要变量/参数的实际结构
③ 元数据与文档配合 Define-XML、aCRF、cSDRG、ADRG，说明补值、分析标志、特殊算法和已知问题
④ 一致性核查核对 CSR 与 TFL、ADaM 与 SDTM、分析集与人群数，以及跨研究术语与分组
⑤ 验证与修复运行适用的标准/业务规则检查，判定错误、警告、允许例外并保留证据
⑥ 问询支持监管审评可能要求附加 Listing、敏感性分析、派生解释、数据重交或说明

一个容易被忽略的问题：提交的不是你“最后一次跑出来的文件夹”，而是受控版本的一整套一致且可复现的交付物。数据、Define、Reviewer Guide、程序、TFL 和 CSR 必须在版本与数值上互相支持。

7. 跨研究整合：ISS / ISE、Integrated ADaM 是什么？

ISS（Integrated Summary of Safety）和ISE（Integrated Summary of Efficacy）关注多项研究证据的整合。实际项目可能建立 Integrated ADaM 或 ISS/ISE 相关分析数据集，用于跨研究安全性或有效性分析；具体结构和递交要求依申报方案及监管要求。

它不仅是将几项 ADAE 简单 SET 在一起。不同试验可能有不同的治疗剂量、访视、TEAE 规则、MedDRA 版本、分析集、单位以及事件观察期。要先协调标准化映射、分析定义、来源 STUDYID、治疗暴露归属和重复入组问题，才可能得到有意义的整合结果。

跨研究差异潜在问题SP 核查方式
MedDRA 版本不同相同 AE 可能对应不同编码统一编码策略/版本，保留来源与映射说明
治疗方案不同不同剂量与疗程直接合并失去解释性建立统一暴露/剂量组并核对时段
实验室单位不同指标数值不能直接合并验证转换与正常范围定义
分析集定义不同混用分母造成比例失真锁定整合分析人群与排除标准
同一受试者跨研究计数可能重复按整合方案管理身份与分析单位

8. 递交之后：受理、审评、问询、批准

以美国 FDA 的常见 NDA/BLA 审评为例：

  1. 提交申请：申办方通过要求的电子流程送交申报包；有传输成功回执不代表申请已通过实质受理。
  2. Filing Review：FDA 初步评估材料是否足够完整，可以开展实质审评；公开流程中 NDA 通常有 60 日受理核查阶段。
  3. 专业审评：临床、统计、药理、药学质量、生产和标签等多学科审阅；可能有信息请求或检查。
  4. 必要时补充：申办方可能提交回应、解释、分析或资料修订；SP 有时需要追加 TFL、核查推导或重新制作支持数据。
  5. 监管决定：批准、完整回复函（CRL）或其他结论；CRL 不是“已经上市”，并可能要求解决问题后再申报。

审评时长不要当成固定倒计时。FDA 对 NDA 标准审评和优先审评有不同目标（常见 10 个月/6 个月），但受理起算口径、申请类型、修改及项目具体情况会影响时间，不应承诺所有产品都在该时间获批。

9. 美国与中国：2026 年两项值得知道的 eCTD 变化

9.1 美国 FDA：eCTD v3.2.2 / v4.0

FDA 官方 eCTD 页面（2026 年 11 月核对）显示，当前支持的版本包括 eCTD v3.2.2 与 v4.0。自 2026-10-16 起，CDER/CBER 还支持原以 v3.2.2 提交的相关申请在特定规则下向 v4.0 的 Forward Compatibility（向前兼容）。不能写成“2026 年起 FDA 只接受 v4.0”。

FDA 2026 年 10 月《Study Data Technical Conformance Guide》还更新了数据递交、Reviewer Guides、Define-XML、可追溯和技术拒收相关说明。具体支持标准需以研究开始日期、适用法规和 FDA Data Standards Catalog 为准。

9.2 中国 NMPA：2026 年 3 月扩大 eCTD 适用范围

中国国家药监局2026 年第 8 号公告规定，自 2026-03-01 起，化学药品、化学原料药和生物制品的药物临床试验申请、上市许可申请、补充申请等可按照 eCTD 方式申报；采用 eCTD 的申请需使用修订后的技术文件。

注意“可按照”并非“所有申请从此必须 eCTD”。此前 2025 年也已有分批扩大试点/使用范围的安排，2026 年公告进一步扩展并调整相关技术文件。

对 SP 的实际启示

不是把美国的 FDA 数据包原封不动发送给 NMPA 就一定符合中国要求。CTD 模块 2–5 的通用结构与地区特定模块、受理制度、电子格式、临床数据要求仍应分别核对当地监管版本。

面试自测

Q1. NDA/BLA 与 eCTD 有什么区别？

NDA/BLA 是美国的监管申请类型；eCTD 是组织和提交申请资料的电子技术标准，不是药物许可证。

Q2. 递交 FDA，是否只要 XPT 和 Define 就够？

通常不够。还要依适用要求准备 Reviewer Guides、aCRF、CSR/SAP、相关程序和其他监管资料，并保证整体一致性与可追溯性。

Q3. 为什么既有 cSDRG 又有 ADRG？

cSDRG 侧重临床表格数据及其特殊情况，ADRG 侧重分析数据和分析解释；都不能代替 Define-XML。

Q4. 一个项目已做完 TFL，是否就可以上市递交？

不是。锁库、分析、CSR、跨研究整合、质量与非临床资料、电子包装与审评都是不同环节。

Q5. 中国 2026 年以后是不是所有化药/生物药都必须 eCTD？

2026 年第 8 号公告明确“可按照 eCTD 方式申报”，不能直接解读为“所有申请必须 eCTD”；需根据当前公告及申报类型核对。

Q6. 为什么说临床统计编程也是上市申报的一部分？

因为监管审评需要能够核查并复现关键疗效和安全性结论，SP 负责的数据、元数据和程序是这条证据链的重要组成部分。
